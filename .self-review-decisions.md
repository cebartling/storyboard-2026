- **experiments/experiment-1/src/lib/app/use-cases.ts:50** — Every use case is an unguarded
  read-modify-write of the whole aggregate; concurrent requests silently lose data
  - **Severity:** high
  - **Reason for rejection:** Fixed in 764c6c8, which added optimistic concurrency.
    `StoryMapRepository.save` now saves only when `map.version` is still current:
    `drizzle-story-map-repository.ts` issues `UPDATE maps ... WHERE id = ? AND version = ?`
    and, on `changes === 0`, distinguishes a stale load from a deleted map inside the same
    transaction. The domain carries `version: number`; `schema.maps` has
    `version integer NOT NULL DEFAULT 0`. A second writer's `save()` now throws rather than
    silently overwriting. The remaining residue — the conflict surfacing as a 400 carrying
    raw internal version numbers — was fixed under finding 4 (`ConflictError` → 409 with a
    message naming the remedy).
  - **Reviewed by:** opus

- **experiments/experiment-1/src/routes/maps/[mapId]/+page.svelte:23** — `handleMove`
  discards the `moveStory` response and has no error path
  - **Severity:** medium
  - **Reason for rejection:** Fixed in 764c6c8. `handleMove` now wraps the fetch in
    `try`/`catch`, reads `deserialize(await response.text())`, sets a `dragError` rune on
    `result.type === 'failure'` (rendered by the `{#if dragError ?? form?.error}` alert),
    uses a distinct message when the fetch itself throws, and calls `invalidateAll()` in a
    `finally` so a thrown request still resyncs the board.
  - **Reviewed by:** opus
